# 纽曼 MF761W USB 供网热点

## Windows 电脑网关扩展

**[下载 v1.2.0 Windows x64 热点服务](https://github.com/greatcorrectandglory/newman-mf761w-usb-router/releases/tag/v1.2.0)**。在支持的 MF761W P005 上，纽曼负责 Wi-Fi 接入和本地 DHCP，Windows 负责加密与公网转发。手机直接连接热点，使用者可配置一个主节点及最多三个备用节点。设备在电脑进程退出时仍可分配地址。

解压发行 ZIP，双击 `Start-Here.cmd`，依次选择本机的 `adb.exe`、`xray.exe` 和私有节点文本文件。运行条件为 Windows x64、64 位 Python、已授权 USB ADB 与兼容 P005 基线。使用本机 Windows 用户登录后，服务自动启动，注册的监控任务负责恢复。扩展沿用现有无线设置，安装过程无需重新刷写 MTD4。[安装、诊断、升级与卸载](extension/README.md) · [扩展验收记录](docs/host-service-results.md) · [源码构建](docs/host-service-build.md)

## 设备端加密与固件

纽曼 MF761W V1.1 OM QX（P005）通过 USB 从 Windows 电脑获取网络，再向手机提供 Wi-Fi 热点。设备负责加密转发、节点切换和灯控，手机无需设置代理。适用基线为原厂 Linux 3.4.110-rt140、8 MiB NOR 闪存和 3,244,032 字节的 MTD4 根分区。

## 工作方式

Windows 通过 USB 向 MF761W 共享网络。手机连接设备的 Wi-Fi 热点后，MF761W 通过用户配置的节点转发流量。节点地址和凭据由用户在本地填写。[节点配置](docs/deployment.md#节点文件)

- 启动时使用**主节点**。当前节点连续两轮检查失败后，按配置顺序尝试下一个备用节点。备用节点连接成功后继续使用。最后一个备用节点也失败时，等待 15 秒，从主节点重新检查。
- **绿灯闪烁**表示加密链路可用，**红灯闪烁**表示连接尚未就绪或正在切换。两种状态均为亮、灭各 0.5 秒。
- 热点公网 IPv4 TCP 与 DNS 经节点转发。公网 IPv6 和其他 UDP 默认阻断。对 QUIC 的 UDP 443 请求立即返回端口不可达，浏览器可回退到 TCP。
- 设备约有 22 MB 系统内存，已利用厂商预留的 12 MiB zram。四条配置保存在设备数据分区，Windows 在设备重启后重新装入运行核心并校时。

## 实测摘要

| 项目 | 2026-11-13 的实测结果 |
| --- | --- |
| 手机系统联网 | 移动数据关闭，手机绑定 Wi-Fi 接口。四轮共 24 次请求全部成功，Android 四轮均判定热点可上网 |
| 手机 Chrome | 切换前 6 次、切换恢复后 3 次均显示页面内容。恢复后百度约 8.23 秒显示内容、48.67 秒完整加载，Google 分别为 4.41 秒和 9.89 秒 |
| 节点切换 | 本次测试中，主节点和前两个备用节点通过检查，第三个备用节点的两项 HTTPS 探测均超时。解除故障后设备自动回到主节点 |
| 设备重启 | 现场软件重启后约 37.8 秒恢复主节点连接，已核对 USB 租约、核心重新装入和校时 |

百度整页加载仍偏慢。上述结果覆盖单台设备、多轮访问和故障恢复，长期运行稳定性和其他硬件版本仍待验证。
