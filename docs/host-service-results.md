# Windows 热点服务验收记录

2026 年 11 月 14 日在一台已有支持基线的 MF761W P005 和一台 Windows x64 电脑上完成。公开安装包和交付前数据平面的测试分列记录。[脱敏测量数据](../evidence/host-service-v1.2.0.json)

## 最终发行包

使用 `newman-hotspot-windows-x64-v1.2.0.zip` 安装到实际 Windows 用户目录与纽曼数据分区。文件大小为 2,537,517 字节，SHA-256 为 `09127de15a6b42ed759cb391aa9a730bd9bf870b8433c1189489082bceff2e23`。两次独立构建产生相同摘要，读回检查覆盖 ZIP 中的 24 个文件。

| 场景 | 现场结果 |
| --- | --- |
| 全新安装 | 从启动安装命令到经主节点验证 HTTPS 在线为 11.9 秒。诊断核对设备身份、安装版本、DHCP 和防火墙规则。 |
| Windows 转发停止 | 在纽曼桥接口发起新的 DHCP 发现与请求，收到 OFFER 和 ACK。默认网关与 DNS 均为电脑网关，设备 DHCP 进程持续运行。 |
| 手动启动 | 从恢复监控检查到在线约 4.1 秒。 |
| 强制结束监督进程 | 监控在 8.6 秒后重新启动服务并通过 HTTPS，纽曼 DHCP 进程保持运行。 |

## 转发与节点恢复

在部署至同一设备的集成构建上，重启专用 ADB 服务后，电脑在 19.4 秒恢复经过节点的 HTTPS，并保留原节点角色。把主节点临时替换为本机的关闭端口后，服务按两轮失败阈值选择第一个备用节点，约 40.1 秒后在线。测试结束后已恢复使用者的原始配置。

向发布网关的本地测试接口同时送入八个模拟客户端的 DNS 请求，八个都收到有效响应并匹配各自的客户端地址；经专用加密代理并发执行的八次 HTTPS 验证也全部成功。此项检验电脑端多客户端转发。同一台纽曼的 `hostapd` 配置读回 `max_num_sta=2`，现场无线实测使用一部手机。两台真实手机同时接入尚待验证。

## 手机上网体验

在打包前的同一分工下，小米 8 关闭移动数据，用 Chrome 清除请求缓存后交替加载百度与 Google 首页。每站三次均收到有效 HTTPS 200、显示内容并完成页面加载。

| 站点 | 首次内容显示 | 整页加载 |
| --- | ---: | ---: |
| 百度 | 1.21–4.82 秒 | 34.39–38.09 秒 |
| Google | 0.58–0.72 秒 | 3.48–3.70 秒 |

百度追加观测中，一项静态资源耗时 36.63 秒。服务运行正常时仍可能出现具体站点的加载延迟。原先出现的手机“IP 配置失败”已通过把 DHCP 放在纽曼本机处理，现场使用者确认重新连接后网页可打开。

本次覆盖单机安装与故障恢复。长时间连续运行、其他硬件型号、电脑注销或重启后的端到端恢复，以及新刷公开镜像的冷启动仍待验证。
